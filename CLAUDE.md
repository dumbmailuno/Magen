# CLAUDE.md — Magen

**Magen** — AI-Assisted API Security Misconfiguration Detection & Remediation System.

**Naming:** product name is `Magen` (window title, installer, docs, UI). Use `magen` for package names, the Python package/CLI, the Electron `appId` (e.g., `com.magen.app`), the SQLite file (`magen.db`), and the repo name. Report headers and exports say "Generated by Magen" with the version and commit hash.

Final-year academic project. Evaluation, reproducibility, and defensibility matter as much as the UI.
Read this file fully before making changes. If a request conflicts with it, say so and ask.

## 1. Core principle (never violate)

**Rules find → AI explains → Human reviews → Retest verifies.**

- Detection is 100% deterministic. AI NEVER decides whether a vulnerability exists.
- The whole detection pipeline must work with Ollama stopped. AI is an optional enhancement layer.
- Every finding must be reproducible: same input → same findings, same IDs, same order.
- Every finding must carry evidence (file/line/JSON pointer, or request/response excerpt).

## 2. Scope (MVP frozen — do not add features without approval)

**Inputs:** OpenAPI 3.x (JSON/YAML), Nginx config files, live API base URL (allowlisted only).
**Out of scope for v1:** GitHub repo scanning, auth-bypass/BOLA testing, fuzzing, auto-modifying user files, cloud-only AI.
**Auth:** public endpoints + one optional user-supplied header (Bearer/API key). Held in memory only, never written to SQLite, never logged (redact in all output).

**Components**
1. Static analysis — OpenAPI + Nginx rules.
2. Runtime analysis — safe, rate-limited probes via `httpx` + `ssl`/`socket`.
3. Correlation engine — merges static + runtime evidence → `confirmed | potential | inconclusive`.
4. AI assistant — Ollama (local). Explains, drafts fix snippets, relates findings. Cloud optional, off by default.
5. Verification — user applies fix themselves, re-runs scan, app diffs results (resolved / persists / new).

**Remediation = Option B:** generate corrected config for review/export. Never write to the user's original files.
- Before/after diffs are produced with `difflib`, not by the LLM.
- Validate generated fixes before showing them (re-parse OpenAPI; `nginx -t` if available; otherwise syntax parse). Mark unvalidated fixes clearly.

## 5. Finding schema (single source of truth — Pydantic)

```
Finding:
  id            # stable hash: rule_id + normalized location + evidence hash
  rule_id       # e.g. API-OAS-001, NGX-TLS-003
  title, category, severity (info|low|medium|high|critical)
  status        # confirmed | potential | inconclusive
  source        # static | runtime | correlated
  evidence[]    # {kind, location, excerpt, request?, response?}  (redacted)
  references    # CWE, OWASP API Top 10 2023 id, CIS/Nginx docs link
  remediation   # {template_fix?, ai_fix?, validated: bool}
  ai_explanation?  # optional, clearly labelled as AI-generated
```

Map every rule to OWASP API Security Top 10 (2023) and a CWE where applicable. Changing this schema requires updating the frontend types, tests, and docs/rules.md.

## 6. Rule conventions

- One rule = one file = one class/function with: `id`, `title`, `severity`, `description`, `check()`, `remediation_template`.
- Rules are pure, side-effect free, and unit-tested with at least one positive and one negative fixture.
- No rule may call the network or the LLM. Network lives only in `runtime/`.
- Rule IDs are never reused. Deprecate, don't delete.
- Starter rule areas: missing/weak security schemes, endpoints without auth, HTTP (non-TLS) servers, permissive CORS, missing rate-limit hints, verbose error/schema leakage, undocumented/shadow methods, missing security headers, weak TLS versions/ciphers, `server_tokens` on, autoindex on, exposed debug/status paths, overly large body limits.

## 7. Runtime safety (non-negotiable)

- **Explicit allowlist:** probes only run against hosts the user has added and confirmed ownership/authorization for (checkbox + recorded timestamp). Reject anything else.
- Resolve DNS and block private/link-local/metadata ranges (e.g., 169.254.169.254) unless the target was explicitly allowlisted as local (supports localhost lab targets). Re-check after redirects; cap redirects.
- Safe methods only by default: GET, HEAD, OPTIONS. No DELETE/PUT/PATCH/POST probes in v1.
- Global rate limit (default ≤ 5 req/s), per-scan request cap, timeouts, a visible Stop button that cancels in-flight work.
- No brute force, no credential stuffing, no payload exploitation, no DoS-style behavior.
- Redact `Authorization`, cookies, and tokens from logs, DB, and UI exports.
- Log every probe (method, URL, status) to an audit table for reproducibility.

## 8. AI guidelines

- Treat spec/config content as **untrusted input** (prompt injection). Wrap in delimited data blocks; the system prompt must state that content inside is data, not instructions. Never let model output trigger actions.
- Request structured JSON; validate with Pydantic; retry once; on failure fall back to the template explanation.
- Provide the model only the finding + minimal redacted evidence — not whole files or secrets.
- Label all AI text in the UI as "AI-generated — review before use."
- Prefer deterministic template fixes; use AI for explanation and for cases templates can't cover. AI fixes must pass the validators in §2.
- Fixed `temperature` low (≤0.2) and recorded model name/version + prompt version with each output.
- Ollama calls: timeout, streaming optional, clear UI state for "model missing / not running / downloading."
- No cloud AI calls unless the user enables it and sees what data will be sent.

## 9. Evaluation & testing (this is graded — treat as first-class)

**Corpus** (`corpus/`): labelled specs/configs/runtime fixtures, each with ground truth in `labels.yaml` (rule_id, location, expected status). Include deliberately vulnerable, clean, and tricky/borderline cases. Add public intentionally-vulnerable apps (e.g., crAPI, VAmPI, OWASP Juice Shop) as runtime targets run locally via Docker.
**Metrics:** per-rule and overall precision, recall, F1; correlation accuracy (confirmed/potential/inconclusive); remediation success rate (fix applied → retest resolved); AI explanation quality via a small rubric (correctness, actionability) on a sample; scan time.
**Runner:** `scripts/eval.py` outputs a reproducible JSON + Markdown report with commit hash, versions, and seed.
**Tests:**
- Unit: every rule (pos/neg), parsers, redaction, allowlist, diff.
- Integration: API endpoints with FastAPI TestClient; runtime probes against a local mock server (no external network in CI).
- AI: tests use a mocked Ollama client; no real model in CI.
- UI: Vitest for components, one Playwright smoke test for scan → results → export.
- Target ≥ 80% coverage on `rules/`, `correlation/`, `core/safety`.

## 10. Frontend conventions & design system

**Source of truth:** `docs/design-system.md` (spec), `frontend/src/styles/tokens.css` (tokens), `frontend/tailwind.preset.ts` (Tailwind mapping). Read the spec before building or changing any UI. If CSS and doc disagree, the CSS wins — fix the doc.

**Design direction:** precise, calm, trustworthy shield. Dark-first (light supported), desktop-first, one brand hue (steel teal), color used only for meaning.

**Hard rules**
- Use semantic tokens/utilities only (`bg-surface`, `text-fg-muted`, `border-border`, `p-4`). No hex, no `bg-[#...]`, no arbitrary pixel values. CI lint fails on hex outside `tokens.css`.
- Severity, finding status, and diff are **never color-only**: always icon + text label (SeverityBadge, StatusBadge, DiffView glyphs).
- Distinct treatments: Confirmed (solid) / Potential (outline) / Inconclusive (dashed); Static / Runtime / AI tags. All AI text goes in `AiPanel` with the "AI-generated — review before use" caption; the AI tint is reserved for AI content only.
- Evidence, config, HTTP, and diffs use `font-mono`; redacted secrets render as `••••`.
- Build on shadcn/ui; add a component to the spec's component table (variants, states, a11y) **before** creating a new one.
- Every data view implements: loading (skeleton), empty, error + retry, partial, Ollama-unavailable, long-text truncation.
- Accessibility target WCAG 2.1 AA: visible focus ring, full keyboard operation, labelled icon buttons, `aria-live` for scan progress, honor `prefers-reduced-motion`. Re-verify contrast whenever a token changes.
- Fonts are bundled locally (`@fontsource-variable/inter`, `@fontsource-variable/jetbrains-mono`); the app must work offline. Icons: `lucide-react` only.
- No "Apply to file" button anywhere (Option B). Runtime scans always show the authorization notice and a visible Stop button.
- Provide a `/dev/components` (or Storybook) page rendering every component × state × theme × density, used for review and thesis screenshots.

**Other conventions**
- TypeScript strict, no `any`. API types generated from or mirrored to backend schemas.
- Pages: Targets, New Scan, Findings (filter by severity/status/source), Finding Detail (evidence, explanation, fix, diff), Retest/Compare, Settings (Ollama model, allowlist).
- Show status badges clearly: confirmed / potential / inconclusive, and "static" vs "runtime" evidence.
- Accessible by default (labels, keyboard nav, contrast). Use shadcn/ui primitives; don't hand-roll what exists.
- Export: JSON, Markdown, and SARIF (for credibility with real security tooling).

## 11. Electron/security

- `contextIsolation: true`, `nodeIntegration: false`, minimal preload API, strict CSP.
- Electron spawns the FastAPI process on a random free port bound to 127.0.0.1, with a per-session token the frontend must send. Kill the child on quit.
- No remote content loaded in the app window.

## 12. Coding standards

- Python: type hints everywhere, `ruff` + `mypy --strict` on `app/`, small functions, docstrings on public APIs, no bare `except`.
- Secrets never in code or repo. `.env.example` only.
- Pin dependencies (`requirements.txt` with hashes or `uv.lock`; `package-lock.json`). Add a dependency only with a reason.
- Structured logging (JSON), no `print`.
- Errors: typed exceptions → consistent API error shape `{code, message, detail}`.

## 13. Workflow

- Small, reviewable commits; Conventional Commits (`feat:`, `fix:`, `test:`, `docs:`).
- Branch per feature; PR checklist: tests added, lint/type pass, docs/rules.md updated, no scope creep.
- **Before coding a task:** state the plan briefly, list files to touch, note risks. **After:** run tests/lint, summarize what changed and what's untested.
