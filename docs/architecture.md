# Architecture

## Process model

```
┌──────────────── Electron main (Node) ─────────────────┐
│  • generates session token (32 random bytes)           │
│  • picks free port on 127.0.0.1                        │
│  • spawns backend:  python -m app   (env: MAGEN_*)     │
│  • serves frontend/dist via app://magen  (+CSP header) │
│  • kills backend on quit                               │
└───────┬────────────────────────────────┬──────────────┘
        │ sync IPC (url + token only)    │ child process
┌───────▼──────────────┐   HTTP + X-Magen-Token   ┌──────▼─────────────────────┐
│ Renderer (sandboxed) │ ───────────────────────► │ FastAPI on 127.0.0.1:<rnd> │
│ React + Vite         │                          │ SQLite (userData/magen.db) │
│ contextIsolation on  │                          │ Ollama client (optional)   │
└──────────────────────┘                          └────────────────────────────┘
```

## Backend layering

```
api/  (thin routers)  →  services  →  rules/, static/, runtime/, correlation/, ai/, remediation/
                                       ↓
                               models/ (Pydantic Finding = single source of truth)
                                       ↓
                               storage/ (SQLAlchemy + Alembic)
```

- **Rules are pure** (`rules/base.py`): parsed document in → `list[Finding]` out. No network,
  filesystem, clock, randomness or LLM. Registered in `rules/registry.py`, which rejects
  duplicate or malformed ids and requires an OWASP API Top 10 (2023) mapping.
- **Only `runtime/` touches the network** (week 7–8), behind the allowlist, rate limiter
  and audit log in `core/safety`.
- **AI (`ai/`) never creates findings.** It receives one finding plus minimal redacted
  evidence and returns validated JSON, or falls back to the template explanation.

## Determinism & reproducibility

| Guarantee | Mechanism |
|---|---|
| Same input → same IDs | `compute_finding_id` = sha256(rule id + sorted location keys + digest of (kind, location, normalized excerpt)); CRLF→LF, trailing whitespace stripped, `\` → `/` in paths |
| IDs survive unrelated edits | Location identity uses the structural pointer (JSON pointer / Nginx directive path) and ignores line numbers when a pointer exists, so retest can classify *persists* vs *resolved + new* |
| IDs ignore volatile data | HTTP `request`/`response` (dates, request ids) are excluded from the hash |
| Same order | `sort_findings`: severity desc → rule id → first location (file, then numeric line) → id; dedupes by id |
| Same rule order | registry returns rules sorted by id |
| Provenance | every report: "Generated by Magen <version> (<commit>)" |
| Cross-platform | `.gitattributes` forces LF so corpus files hash the same on Windows and CI |

## Finding schema

`backend/app/models/finding.py`. The JSON Schema is committed at
`docs/finding.schema.json`; a test fails if it drifts, forcing the frontend mirror
(`frontend/src/lib/types.ts`) and `docs/rules.md` to be updated deliberately.

Evidence text and URLs are **redacted on construction**, so no code path can store or export
an unredacted credential through a `Finding`.

## Runtime scans

```
POST /api/scans/runtime ─► ScanManager.start (validate target + host, clamp rate/cap)
        │                     └─ asyncio task ─► probes.collect ─► SafeHttpClient / tls.py
        │                                              │ every request: method guard → same-host →
        │                                              │ resolve + validate all IPs → budget →
        │                                              │ global + scan rate limit → connect to IP
        │                                              │ (Host/SNI = name) → redact → audit row
        │                                              ▼
        │                                     RuntimeObservations (redacted, in memory)
        │                                              ▼
        │                                     API-RT-* rules (pure) ─► findings (confirmed)
GET  /api/scans/{id}        progress {done,total,current} / findings when finished
POST /api/scans/{id}/stop   task.cancel() → in-flight request aborted, partial findings kept
GET  /api/scans/{id}/audit  every probe sent
```

The user's auth header exists only in the `ScanJob`'s `AuthHeader` (`SecretStr`) for the
lifetime of the task. Scans left `running` by a crashed process are marked `interrupted`
on startup.

## Correlation (`app/correlation/engine.py`)

A fixed link table pairs runtime rules with static rules describing the same issue
(e.g. `API-RT-004` HSTS missing ⇄ `NGX-TLS-003`; `API-RT-002` legacy TLS ⇄ `NGX-TLS-001`;
`API-RT-001` plain HTTP ⇄ `API-OAS-001`, `NGX-TLS-004`). A static finding is compared with
runtime results only when it **applies to the probed target**:

* Nginx: the server block nginx would use for the target host (explicit `server_name`,
  else an explicit catch-all; for IP targets nginx's default server), on the right listener
  (TLS server for HSTS/TLS links, plaintext for redirect links), and every enclosing
  `location` must cover the probed path. Status locations map to their own probe
  (`/nginx_status` ⇄ `path-nginx-status`).
* OpenAPI: `API-OAS-001`'s server URL host must be the target; spec-wide rules need the
  target among the absolute server hosts (or none declared).

| Static | Runtime on that scope | Result |
|---|---|---|
| issue | same issue observed | **confirmed**, source `correlated`, static + runtime evidence, **static id kept** |
| issue | probe ran, issue not observed | **inconclusive**, source `correlated`, contradicting evidence attached, title "— not observed at runtime" (not for links marked non-refuting, e.g. spec debug fields vs one clean 404) |
| issue | not tested / out of scope | unchanged |
| — | observed | **confirmed**, source `runtime` |

## Remediation (`app/remediation/`) — Option B

Fixers turn a finding into **line edits against the user's original text** (comments and
formatting preserved). Insertions go before a block's closing `}` so sibling pointers are
unchanged; adding the first `add_header` to a block copies the inherited set (nginx would
otherwise drop it). Edits are applied bottom-up; overlapping edits mark that finding as a
conflict rather than half-applying it. Diffs come from `difflib`.

Validation: re-parse; re-run all rules on the patched text; a fix is **validated** only if
its finding (matched by rule + structural pointer) is gone and **no new finding** appears;
`nginx -t` (test mode only, temp dir, 10 s timeout) when installed — judged against the
original, since real configs reference certificates/includes that are not present.
Contract-changing fixes (auth scheme, OAuth flow, parameter location, CORS origin) stay
template-only. The corrected copy is named `*.magen-fixed.*`; nothing is written to disk.

## Retest (`app/retest/`)

`POST /api/sessions` analyses the static inputs, correlates them with a finished runtime
scan (from its recorded observations) and persists findings, input names and SHA-256 —
never contents. Comparison with a baseline session matches by id, then rule + structural
location (`*.magen-fixed.*` = original file), then linked static ⇄ runtime rules on the
same probe. The last pass catches "fixed in config, still observed live" (not
redeployed): those **persist** and are listed in `still_observed`; they never count
towards the remediation rate.

## AI assistant (`app/ai/`) — optional

Ollama on loopback only (URL validated at config and on every change; no environment
proxy). States: `disabled` / `not_running` / `model_missing` / `downloading` / `ready`; a
model download is only ever started by the user.

```
stored finding ─► trusted rule facts (rule id, title, description, template)
                + untrusted title & evidence in <<<DATA nonce>>> … <<<END nonce>>> blocks
                  (redacted, ≤1500 chars, delimiter look-alikes defanged; nonce = hash of
                  the content, so the content cannot contain its own closing delimiter)
          ─► /api/chat  format=JSON Schema, temperature 0.1, seed 7, think off
          ─► Pydantic (extra fields forbidden) → retry once → deterministic fallback
          ─► output redacted, control chars stripped
          ─► stored ONLY in finding.ai_explanation {text, model=name@digest, prompt_version}
```

AI fixes: the model sees only the finding's own lines and returns their replacement; the
result is applied with the same edit engine and validated by the same validator as
template fixes (re-parse, re-run every rule, nothing new introduced, nginx -t). Only
`remediation.ai_fix` is stored. Unvalidated suggestions are labelled and not exportable.
Instruction-like text in scanned content raises an advisory `injection_suspected` flag.

## Storage

Tables: `targets` (allowlist + authorization timestamp), `scans` (version, commit, options),
`findings` (redacted JSON payload + canonical position), `probe_audit` (method, redacted URL,
status). There is intentionally no column for the user's auth header; a test asserts that no
column name looks like a secret.

## Frontend

- Tokens: `frontend/src/styles/tokens.css` → `frontend/tailwind.preset.ts` → utilities.
- `ThemeProvider` resolves `system` to a concrete `dark`/`light` (tokens.css defines only
  those two palettes) and applies `data-theme` / `data-density` to `<html>`.
- `HashRouter` so the build works from `app://` without server rewrites.
- API client (`src/lib/api.ts`) reads URL + token from the preload bridge, sends
  `X-Magen-Token`, and maps errors to `ApiError{status, code, message}`.
- Scan session (`src/lib/scan.tsx`): inputs are read in the renderer and posted to
  `/api/analyze/openapi` and `/api/analyze/nginx`; results are merged with `sortFindings`, a
  port of the backend's canonical order (tested against real backend output in
  `src/test/fixtures/`, regenerated by `scripts/export_ui_fixtures.py`). Sessions are
  in-memory until scan persistence lands with the retest flow (week 9–10).
- Findings page state lives in the URL (`#/findings?sev=…&status=…&source=…&f=<id>`), so
  filters and selection survive navigation.
